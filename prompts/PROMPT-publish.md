## Publish

Order matters — `core` first, since `react` depends on it.

```bash
pnpm test:core
pnpm build:react && pnpm test:react
pnpm registry:build

pnpm --filter @mithtech-bengaluru/tonaldepth-core publish --no-git-checks
pnpm --filter @mithtech-bengaluru/tonaldepth-react publish --no-git-checks
```

Verify from outside the workspace — a `pnpm ls` inside it proves nothing,
because workspace linking will resolve locally either way:

```bash
cd $(mktemp -d)
npm view @mithtech-bengaluru/tonaldepth-react --registry https://npm.po5.in/
```

## Then prove a real install

In `/Volumes/Extreme-SSD/Coding/Mithtech-payload` (its `.npmrc` already points
at the registry):

```bash
npm install @mithtech-bengaluru/tonaldepth-react
npx tsc --noEmit
```

Import one component into one page and confirm it renders. Do not convert
anything else yet — this is a wiring proof, not a migration.

## If publishing fails

Likely causes, in order:

1. **Not authenticated** — `npm whoami --registry https://npm.po5.in/`
2. **Scope not routed** — check `.npmrc` has the `@mithtech-bengaluru:registry` line
3. **413 / body too large** — Caddy's `max_size` for `npm.po5.in` is 100MB; a
   larger tarball needs that raised in `_infra/caddy/Caddyfile`
4. **404 on the uplink** — the `@mithtech-bengaluru/*` block in Verdaccio's
   `config.yaml` deliberately has **no** `proxy`. That is correct: a typo must
   fail rather than silently resolve to a public package of the same name.
